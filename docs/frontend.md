
# Архітектура frontend SolarFlow

## 1. Загальний опис

SolarFlow — вебплатформа для моніторингу та керування сонячною енергосистемою.

Frontend реалізовано на основі Astro, який виконує роль головної оболонки застосунку. Для розробки інтерактивних модулів використовуються React, Vue та Svelte. Їх інтеграція здійснюється за допомогою архітектурного підходу Astro Islands.

Основні завдання frontend:

- Забезпечення єдиного інтерфейсу та навігації.
- Відображення даних про виробництво й споживання електроенергії.
- Інтеграція модулів, створених на різних JavaScript-фреймворках.
- Обмін даними між компонентами через Nano Stores.
- Взаємодія з backend через REST API.

## 2. Використані технології

| Технологія | Призначення |
|---|---|
| Astro | Оболонка застосунку, маршрутизація та макети сторінок |
| React | Інтерактивні компоненти, зокрема модуль моніторингу |
| Vue | Компоненти конфігурації та керування енергосистемою |
| Svelte | Компоненти симуляції та візуалізації |
| TypeScript | Типізація даних і програмних інтерфейсів |
| Nano Stores | Спільне реактивне сховище стану |
| Vitest | Автоматизоване тестування frontend |

## 3. Структура проєкту

Основні директорії frontend:

- `src/layouts/` — спільні макети сторінок Astro.
- `src/components/shared/` — компоненти загального інтерфейсу.
- `src/components/react/` — компоненти React.
- `src/components/vue/` — компоненти Vue.
- `src/components/svelte/` — компоненти Svelte.
- `src/pages/` — сторінки застосунку та маршрути.
- `src/stores/` — спільне сховище стану.
- `src/lib/` — допоміжні засоби взаємодії з REST API.
- `src/types/` — інтерфейси та типи TypeScript.
- `src/styles/` — спільні CSS-стилі та змінні.

## 4. Astro Shell і маршрутизація

Astro формує основну структуру застосунку та забезпечує файлову маршрутизацію.

Головний макет розташовано у файлі:

`src/layouts/Layout.astro`

До спільних компонентів інтерфейсу належать:

- `Header.astro` — верхня частина інтерфейсу.
- `Navigation.astro` — навігація між сторінками.
- `ModulePlaceholder.astro` — тимчасовий компонент для сторінок модулів, які ще не інтегровані.

Основні маршрути:

| Маршрут | Призначення |
|---|---|
| `/` | Головна сторінка |
| `/features` | Огляд можливостей платформи |
| `/service` | Сервіс і підтримка користувачів |
| `/dashboard` | Моніторинг енергосистеми |
| `/configurator` | Конфігурація сонячної електростанції |
| `/smart-grid` | Модуль Smart Grid |
| `/finance` | Фінансові та екологічні показники |
| `/simulation` | Симуляція роботи енергосистеми |

Частина маршрутів наразі містить тимчасові компоненти. Після завершення розробки командних модулів вони будуть замінені на повноцінні інтерактивні інтерфейси.

Для перевірки окремих функцій також створено:

- `/store-test` — демонстрація роботи спільного стану.
- `/api-test` — перевірка взаємодії з REST API.

## 5. Інтеграція React, Vue та Svelte

Для поєднання компонентів різних фреймворків використовується підхід Astro Islands.

Кожен інтерактивний компонент працює як окремий «острів» усередині Astro-сторінки.

Приклад підключення:

```astro
<ReactComponent client:load />
<VueComponent client:visible />
<SvelteComponent client:idle />
```

Директиви керують моментом активації інтерактивності:

- `client:load` — завантажує та ініціалізує компонент під час завантаження сторінки.
- `client:visible` — активує компонент після появи в області видимості.
- `client:idle` — відкладає активацію до періоду простою браузера.

Це дозволяє поєднувати кілька фреймворків у межах одного застосунку без необхідності створювати для кожного окрему систему навігації.

## 6. Керування спільним станом через Nano Stores

Для обміну даними між компонентами React, Vue та Svelte використовується бібліотека Nano Stores.

Основний файл:

`src/stores/energyStore.ts`

Типи даних:

`src/types/energy.ts`

Сховище містить інформацію про стан енергосистеми, зокрема:

- потужність генерації сонячної енергії;
- поточне споживання електроенергії;
- рівень заряду акумулятора;
- потужність акумулятора;
- обмін електроенергією із зовнішньою мережею;
- час останнього оновлення;
- статус системи.

У сховищі реалізовані функції:

- `updateEnergyMetrics()` — оновлення енергетичних показників.
- `updateSystemStatus()` — зміна статусу системи.
- `resetEnergySystem()` — повернення до початкового стану.

Для перевірки роботи Nano Stores створено демонстраційні компоненти на React, Vue та Svelte.

На сторінці `/store-test` можна перевірити синхронне оновлення даних між компонентами різних фреймворків.

## 7. Взаємодія з backend через REST API

Для взаємодії з серверною частиною реалізовано окремий REST API Client.

Основні файли:

- `src/lib/apiClient.ts` — універсальний клієнт HTTP-запитів.
- `src/lib/applianceApi.ts` — операції з електроприладами.
- `src/types/appliance.ts` — типи даних електроприладів.

REST API Client забезпечує:

- надсилання HTTP-запитів;
- обробку відповідей сервера;
- отримання JSON-даних;
- обробку помилок HTTP і мережевих з'єднань.

Для електроприладів реалізовано основні CRUD-операції:

| Операція | HTTP-метод | Призначення |
|---|---|---|
| Read | GET | Отримання списку або окремого приладу |
| Create | POST | Створення нового приладу |
| Update | PUT | Оновлення даних приладу |
| Delete | DELETE | Видалення приладу |

Адреса backend задається через змінну середовища `PUBLIC_API_URL`.

Приклад локального налаштування у файлі `frontend/.env`:

```env
PUBLIC_API_URL=http://localhost:5106
```

Для роботи HTTP-запитів сервер має бути запущений, а політика CORS — дозволяти звернення з адреси frontend.

Перевірка підключення виконується на сторінці `/api-test`.

## 8. Локальний запуск frontend

Для роботи із frontend необхідно встановити Node.js та npm.

У терміналі потрібно перейти до директорії frontend:

```powershell
cd frontend
```

Встановити залежності:

```powershell
npm install
```

Запустити сервер розробки:

```powershell
npm run dev
```

За стандартних налаштувань Astro сторінка буде доступна за адресою:

`http://localhost:4321`

Для створення production-збірки:

```powershell
npm run build
```

Для перевірки Astro та TypeScript:

```powershell
npx astro check
```

## 9. Автоматизоване тестування

Для тестування frontend використовується Vitest.

Тестові файли:

- `src/stores/energyStore.test.ts`
- `src/lib/apiClient.test.ts`

Тести Nano Stores перевіряють:

- початковий стан сховища;
- оновлення енергетичних показників;
- зміну статусу системи;
- скидання стану до початкових значень.

Тести REST API Client перевіряють:

- успішне отримання JSON-відповіді;
- обробку HTTP-помилки 404;
- обробку відповіді 204 без вмісту;
- обробку помилки мережевого з'єднання.

Загалом реалізовано 8 автоматизованих тестів.

Для запуску тестів:

```powershell
npm test
```

Автоматизовані тести дозволяють перевіряти роботу сховища та API-клієнта незалежно від фактичного підключення до backend.

## 10. Правила інтеграції командних модулів

Для інтеграції нового модуля необхідно:

1. Розмістити компонент у відповідній директорії `react/`, `vue/` або `svelte/`.
2. Імпортувати компонент до відповідної Astro-сторінки.
3. Додати директиву гідратації, якщо компонент потребує інтерактивності в браузері.
4. Використовувати спільні TypeScript-типи для узгодження структури даних.
5. Підключатися до Nano Stores, якщо потрібен доступ до спільного стану.
6. Використовувати REST API Client для підтримуваних серверних операцій.
7. Перевірити роботу модуля, тестування та production-збірку.
8. Оформити зміни в окремій Git-гілці через Pull Request.

Під час інтеграції потрібно зберігати загальний макет і навігацію SolarFlow та уникати непотрібних змін у компонентах інших учасниць.
